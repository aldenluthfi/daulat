## Behavior decisions

- **Node visibility = content-mask, not a selection gate (user decision).**
  The plan's literal "reject hidden nodes" wording contradicts GDD, which
  describes fixed visible map layouts with reveal as an information peek. Per
  the user's call, `revealed` now governs whether a node's identity/content is
  shown, never whether it can be selected. `map_generate` reveals node 0 and
  its direct successors; every clear/skip/win reveals the cleared node's
  successors; `run_emit_map` masks unrevealed nodes as `type=-1 name="?"
  modifier=-1` while keeping `i`, `cleared`, and `selectable` truthful. This
  makes reveal effects behavioral without adding movement gating GDD omits.
- **Reveal events auto-reveal deterministically (user decision).**
  `eff_ev_reveal` folds through `run_node_reveal`, revealing the next N hidden
  nodes in graph index order. No `target i=N` round-trip for reveals.
- **Typed run interaction mirrors the battle card-target model.** Event
  options advertise candidates through `QUERY_EVENT_TARGETS` (one slot per
  step) and resolve through `ON_EVENT_TARGET_SELECTED`, exactly like
  `QUERY_CARD_TARGETS`/`ON_CARD_TARGET_SELECTED`. `run_event_choose` fires
  immediate `ON_EVENT_CHOOSE` effects through `run_fire`, then parks a typed
  interaction; `run_event_target` records each pick; a single
  `run_interaction_advance` builds the next step or resolves and completes.
- **`TARGET_FIGUREHEAD` added (KingdomID).** The plan's four-kind vocabulary
  (`TARGET_CARD/RELIC/PIECE_TYPE/NODE`) does not cover chain figureheads, but
  Desert Crossing's "any figurehead" requires a chosen chained kingdom, so a
  fifth run domain kind was added and documented.
- **Piece-type picks persist via `event_picks`.** Janggi Elder and Forge
  Master record the chosen `PieceID` in `run->event_picks[event]` (`-1` =
  none), serialized as `eventpick i=E value=V`. `battle_walk_run_effects`
  re-attaches the option's persistent value/cost effect each battle and
  overrides its `-1` sentinel `args[1]` with the restored pick. This removes
  the fixed `PIECE_XIANG`/`PIECE_KYOSHA` representatives. (Veteran Lance's
  "All Kyosha +5" stays a fixed `EV_VAL_PIECE(PIECE_KYOSHA)` per GDD; it is
  not a choice.)
- **`run_fire` is the generic run-side dispatch.** It walks the pending
  option's effects through the shared invoke-and-log path (via the new public
  `effect_trigger_name`), the non-battle analogue of `effect_fire`. Run
  operation metadata lives in the file-static pending state, never in `x`.
  Relic/archive-count composition over held relics is F3+; F2 establishes the
  vehicle and routes event resolution through it.
- **Old event continuation branches removed.** Card-removal, relic, skip, and
  chain-figurehead event paths now flow through the typed interaction, so
  `run_offer_relics`, `run_begin_removal`, `run_skip_battle`, the
  `skip_next_battle` field, and `PENDING_REMOVALS` were deleted. `run_offering`
  (offering nodes) and `run_relic_pick` (elite/overseer offers) keep their
  `remove`/`relic` commands — those are non-event continuations, not part of
  the event-choice path the gate covers.
