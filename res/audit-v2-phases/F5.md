## Behavior decisions

- **`modifier_revealed` is a per-node dimension orthogonal to `revealed`.**
  `revealed` gates node identity (`type`, `name`); `modifier_revealed` gates
  only the `BattleModifier` index. A normally-revealed battle node now emits
  `modifier=-1` until its modifier is separately revealed — the map screen no
  longer leaks the modifier for free. This is the F5 correction of the F2 flag
  that conflated the two. `run_emit_map` masks the modifier on
  `modifier_revealed`, node identity still on `revealed`.
- **The Defector A changed from a node-identity reveal to a modifier reveal.**
  Per GDD it reveals "the next battle's modifier". Option A now carries
  `{EV_TG_MODIFIER, EV_SEL_MODIFIER}` and resolves through the existing typed
  interaction (`QUERY_EVENT_TARGETS` → `target i=N` → `ON_EVENT_TARGET_SELECTED`)
  exactly like skip-node. Candidates are revealed, uncleared battle nodes whose
  modifier is still hidden (`run_targets_modifier_nodes`); the resolver lifts
  only the modifier mask (`run_reveal_modifier`). `node_selectable` was **not**
  required for candidacy — an event node and a battle node rarely share the
  frontier, and "the next battle" is a scouting peek at revealed battles ahead,
  not a node you must be able to enter this instant.
- **F2 node-reveal events unchanged.** Spy Network and Desert Crossing keep
  `EV_REVEAL(n)` → `eff_ev_reveal` → `run_node_reveal` (node-identity reveal,
  `log reveal node=`). `run_node_reveal`, the `EV_REVEAL` macro, and
  `eff_ev_reveal` are byte-for-byte unchanged; only Defector's option list moved.
- **Surveyor's Map fires generically on map entry.** New `ON_MAP_ENTER` trigger
  dispatched by the existing `run_fire_relics` from `run_enter_map`. The relic
  effect (`eff_surveyors_map`, in the data layer) calls one generic run helper
  `run_reveal_map_modifier`, which names no relic.
- **Deterministic pick, no per-map flag (recorded user decision).** Surveyor
  picks a battle node with `rng_mix(run->seed, kingdom*3 + tier) % battle_count`
  — the same per-map seed used to generate the map. The pick is idempotent, so
  re-entering reveals the *same* node's modifier and never a second one. Because
  `modifier_revealed` is already persisted per node, no `MapState` "applied"
  field and no extra save token are needed. This deviates from the plan's
  "store per-map application" wording but yields identical observable behavior
  with less persistent state, matching F4's deterministic-projection approach.
- **Save format extended backward-compatibly.** Each `map` line gains a
  ` modrev=<bits>` token after `revealed=`. The loader parses with five
  specifiers and accepts a match of 4 (legacy save — all modifiers default
  hidden) or 5 (new save — restore the bits). `run_fire_relics` was relocated
  above `run_enter_map` to keep the codebase's strict definition-before-use
  ordering (no forward declarations added).

### 1. Split visibility (Longwei Town, default)

```text
enter id=0 / nodes
node i=0 type=0 name="The Copper Gate"  revealed=1 ... modifier=-1   (identity

                                                                     hidden)
```

Revealed battle/elite nodes now emit `modifier=-1`; deeper nodes fully masked.
Negative: a fresh map with no relic shows every `modifier=-1`.

### 2. Defector modifier reveal (Longwei Province, node 10 = "The River
Crossing Post"; patch town cleared, province node 9 cleared so node 10
selectable, all revealed)

```text
select i=10 / choose a
target -> i=0..4 kind=5 value=0..4          (revealed uncleared battle nodes;
                                             elite/event/cleared excluded)

  -> log reveal modifier=2
     log effect name="Modifier Reveal" trigger=ON_EVENT_TARGET_SELECTED

         node i=3 ... modifier=-1            still hidden)
```

Probes: after resolve, `target i=0` -> `error msg="no pending target"`;
`target i=99` -> `error msg="no pending target"`.

### 3. Surveyor's Map (Longwei Town, `relics` bit 22 set)

```text
enter id=0
  -> log reveal modifier=4
     log effect name="Surveyor's Map" trigger=ON_MAP_ENTER
nodes -> node i=4 ... modifier=7            (exactly one node; others -1)
back / enter id=0 / nodes
  -> log reveal modifier=4                  (SAME node 4 re-revealed;
     node i=4 ... modifier=7                 idempotent, no second modifier)
```

Negative: without the relic (case 1) no modifier is pre-revealed.

### 4. Save/load persistence

```text
(Defector reveal of node 2, then) back / save
saved: map k=0 t=1 cleared=00000000011 revealed=11111111111 modrev=00100000000
load / enter id=0 / nodes -> node i=2 ... modifier=5   (modrev bit persists)

backward compat: strip " modrev=..." from the saved line -> 4-field legacy line
load / enter id=0 / nodes -> node i=2 ... modifier=-1  (parses, defaults hidden)
```

### 5. F2 node-reveal preserved (Spy Network, Harushima Town node 10; clear
node 9, reveal node 10, leave others hidden)

```text
select i=10 / choose a
  -> log reveal node=2
     log reveal node=4
     log reveal node=5
     log effect name="Reveal" trigger=ON_EVENT_CHOOSE
```

Node **identity** reveal still logs `reveal node=`, distinct from the modifier
reveal path.
