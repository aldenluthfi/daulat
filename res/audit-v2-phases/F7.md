## Behavior decisions

- **No new `RunState`/`MapState` field for the trial (user no-state-bloat
  philosophy).** The trial's whole lifecycle is derived from the already
  persisted `chains=` (which kingdom is Gold) and `liberation_at[]` (respawn
  timer). On load, `run_new` rebuilds layout-only maps and `liberation_sync`
  re-injects the trial; the injected node is never serialized. Only the recipe
  ban needed one new persisted array (`recipe_forbidden[]`, saved as
  `forbidden=`).
- **Trial win → full liberation (recorded user decision).** A trial win sets
  `kingdoms[subjugated].chain = nullptr` (not a one-step `chain_remove`); the
  track unlocks with no residual Bronze/Silver.
- **Trial is non-blocking (recorded user decision).** `map_complete` skips
  `MAP_NODE_LIBERATION`, so the host tier finishes normally; a still-pending
  trial re-homes into the host kingdom's new active-tier map because
  `liberation_sync` targets `active_map`. A stale node left in a completed tier
  is never emitted (that map is no longer active).
- **Trial is immediately selectable when its timer is ready.** `node_selectable`
  returns `battles_fought >= liberation_at[subjugated]` for a liberation node,
  independent of graph predecessors, so the intrusion can be tackled at once and
  is locked for exactly three battles after a loss.
- **+2 army and restricted draw are effects, not node-type branches.** The
  hardcoded `+2` at `battle_setup_armies` is removed; `liberation_attach`
  installs a `QUERY_ENEMY_ARMY_COUNT` `+2` effect and a `QUERY_CARD_CAN_DRAW`
  veto keyed to the subjugated kingdom (only its cards remain drawable, per
  literal GDD — universal cards are excluded too).
- **`x` stays the payload.** `QUERY_RECIPE_ALLOWED` is `bool *`; the candidate
  recipe index travels through `battle_subject_recipe()`, never a wrapper.
- **Threshold identity stays in the Vorath item.** `run.c` only counts losses
  generically; `vorath_forbid_recipe` (in `universal.c`) owns the every-four
  boundary choice and deterministic pick `rng_mix(seed, vorath_counter)`.
- **Documented deviation:** the Gold track lock reads
  `chain == &CHAIN_REGISTRY[CHAIN_GOLD]` in two generic run sites
  (`liberation_sync`, the `run_select_node` guard). This is a read of generic
  chain *state*, the same class as `battle_setup_armies` already deriving the
  chain level — not an item-identity branch. The map emit still reports per-node
  reachability; the track-level lock is authoritative at `select`.
